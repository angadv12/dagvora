What the scheduler does
Find ready tasks→Start workers→Wait for a finish→Update state ↺
It checks again after a worker finishes. The API can start while docs are still running.
Scheduler decides when work starts.
Executor.execute(spec) performs the work.
Normal return = completed. An ordinary exception = failed.
asyncio lets work overlap while tasks wait.
It does not make CPU-heavy Python run in parallel.
The current workers in tests are fakes; no LLM runs yet.


Allowed state changes
PENDING→READY→RUNNING→COMPLETED / FAILED
Other changes raise InvalidTransitionError without changing the state. “Blocked” is a final report label for tasks still pending, not another stored state.


The diff, one piece at a time


TaskSpec — validated task descriptions
models.py adds an ID, title, and optional description. Pydantic rejects empty IDs and titles. frozen=True prevents field reassignment. The spec holds no dependencies or progress.


TaskGraph — dependencies move out of Task
graph.py replaces the old Task dataclass with TaskSpec. dependencies["api"] = {"db"} says what API needs. dependents["db"] = {"api"} says what waits for the database.
The existing cycle check rejects a new A → B edge if B already leads back to A. Both maps change only after validation. Topological sorting returns a valid order; it does not execute work or remove real edges.


ExecutionState — one place to change progress
state.py registers IDs as PENDING and checks each requested transition against the allowed moves above. It can find IDs in a given state and return a copy of the current state map.


Scheduler + Executor — when to run, and what to run
scheduler.py promotes a pending task only when all its prerequisites are COMPLETED. No prerequisites means it can become ready immediately. It starts ready workers with asyncio.create_task and tracks each running task by ID.
asyncio.wait(..., FIRST_COMPLETED) waits for at least one finish, rather than the whole batch. The Executor protocol describes the required async method; the worker object supplies that method.


RunSummary — completed, failed, blocked
An ordinary worker exception fails only that task. Independent work continues. When nothing is running, the scheduler returns sorted ID tuples and a final state snapshot. It does not retry or save the run to disk.


Tests, exports, and docs
Graph tests now use TaskSpec. New tests cover validation, state changes, dependency order, overlapping work, and failures. Async tests use events to control ordering instead of timing guesses. __init__.py exposes the new classes; README and project context describe Stage 2.
